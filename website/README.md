# Локальный сайт КиноЖдун

Сайт использует существующий Python-стек; новые зависимости не нужны.
Запуск из корня проекта:

```powershell
.venv/Scripts/python.exe -m website
# либо
powershell -ExecutionPolicy Bypass -File ./start_site.ps1
```

Адрес: http://127.0.0.1:8099. Оставьте процесс работающим: фоновая
редакция запускается при старте и затем каждый час. При выключенном компьютере
или остановленном процессе новые материалы не создаются.

## Что реализовано

- Адаптивная главная, новости, фильмы, сериалы, календарь, статьи, поиск и пагинация.
- Прямые ссылки в существующий бот `c_movie_ID` / `c_tv_ID` и канал.
- Автономная редакция сравнивает снимки TMDB: новые даты, изменения дат,
  изменение статуса, наступление даты выхода, новые официальные трейлеры.
- При первом запуске создаются статьи о ближайших датах. Статьи про трейлеры
  и статусы появляются при изменениях между проверками, а не из старого каталога.
- Опубликованные подтверждённые сообщения канала импортируются без записи
  в базу бота; подозрительные даты в недельных дайджестах отфильтровываются.
- Уникальный отпечаток события предотвращает повторные публикации после рестартов.
- Начальный каталог добавляет только отсутствующие будущие проекты. Перезапуск
  не заменяет снимки TMDB и не возвращает удалённые редакцией проекты.
- Материалы и снимки сохраняются в `data/website.db`; база бота не изменяется.
- Нет отправки сообщений или изменения режима публикации в Telegram.
- HTML формируется на сервере; canonical, Open Graph, Article/NewsArticle,
  `sitemap.xml`, `robots.txt`, `feed.xml`, человекочитаемая страница 404.

## Автоматизация и источники

Используется `TMDB_API_KEY` из существующего `.env`. При сбое сети сайт сохраняет
контент и автоматически пробует снова на следующем цикле. `/health` показывает
последний успешный цикл, ошибки и количество материалов. Секреты в ответ не попадают.
Каталог новых фильмов и сериалов ограничен популярными результатами TMDB;
Фильмы дополнительно выбираются по международной дате премьеры в следующие 120 дней.
это не полный мониторинг всех новостей киноиндустрии. Интервью, слухи, пресс-релизы
и рецензии пока не собираются. Для такого расширения нужны дополнительные разрешённые
источники. AI-ключ не нужен: текст формируется из проверяемых данных по шаблонам.

TMDB — каталог сообщества, а не официальный пресс-центр. Даты могут различаться по
регионам. Для сериалов используется следующий эпизод, а не дата первого сезона.
Пользователю показываются источник и эти ограничения. Права и условия использования:
https://developer.themoviedb.org/docs/faq

## Конфигурация

Все `SITE_*` параметры необязательны. Значения по умолчанию приведены в `.env.example`.
`SITE_CHANNEL_URL` нужен, если `TELEGRAM_CHANNEL_ID` содержит числовой ID вместо username.
`SITE_DATABASE_PATH` позволяет переопределить путь собственной базы сайта.
`SITE_SYNC_INTERVAL_MINUTES=60`, `SITE_BATCH_SIZE=12` задают период и объём выборки.
Можно применять `HTTPS_PROXY` через окружение для подключения к TMDB.
Проверка TLS-сертификатов включена; для собственного доверенного центра
сертификации можно задать `SSL_CERT_FILE`. Ошибка сертификата сохраняется в `/health`.

Локально индексация отключена. Для публичного размещения нужны:

1. Постоянно работающий сервер, HTTPS и домен.
2. `SITE_BASE_URL=https://ваш-домен` и `SITE_PUBLIC=true`.
3. Запуск сайта как сервиса с автоматическим перезапуском; готов вариант Docker Compose.
4. Добавление `/sitemap.xml` в Google Search Console и Яндекс Вебмастер после размещения.

В репозитории настроены Caddy для `kinojdun.ru` / `www.kinojdun.ru` и Docker Compose
с отдельными контейнерами бота и сайта. Наличие этой конфигурации не подтверждает
текущую доступность сервера. SEO-разметка помогает поисковикам понимать страницы,
но не гарантирует позиции или индексацию:
https://developers.google.com/search/docs/appearance/structured-data/article

## Серверный запуск и обновление

`start.sh` получает код в `/root/kinozhdun`, сохраняет существующий `.env` и запускает
контейнеры. Если `.env` отсутствует, скрипт создаёт его из `.env.example` и останавливается
до заполнения ключей. Токены хранятся только в `.env`, который исключён из Git.

Для публичного размещения задайте `SITE_BASE_URL=https://kinojdun.ru`,
`SITE_PUBLIC=true` и настройки канала. Порт и адрес прослушивания сайта задаёт Compose.
После заполнения конфигурации повторно выполните `bash start.sh`.

`auto_deploy.sh` устанавливает SSH-ключ, запускает контейнеры и добавляет cron-задачу
проверки ветки `master` каждые две минуты. Запускайте его после подготовки `.env`.
Обновление использует `git reset --hard`: локальные изменения отслеживаемых файлов
на сервере будут заменены при первоначальной настройке. Задача cron использует
`git merge --ff-only`, предотвращает одновременные сборки и повторяет неудавшийся
деплой на следующем цикле. Каталог `data/` и `.env` исключены из Git.

Compose использует DNS `9.9.9.9` и `149.112.112.112`: проверенные на сервере
альтернативы возвращают рабочие адреса TMDB. Для бота задан адрес Telegram API
через `extra_hosts`; имя `api.telegram.org` и проверка TLS сохраняются.
Адрес можно обновить переменной `TELEGRAM_API_IP` в `.env`, затем пересоздать
контейнер бота. Если доступность этого адреса изменится, его потребуется проверить заново.

Дайджесты бота используют `Europe/Moscow`: ежедневный — в `DAILY_DIGEST_HOUR:30`,
недельный — в `WEEKLY_DIGEST_HOUR:00` выбранного дня.

Ключи, ранее попавшие в `start.sh`, остаются в истории Git. Удаление из текущего файла
не отзывает их: замените токен бота и ключ TMDB у соответствующих сервисов и обновите
локальный и серверный `.env` перед перезапуском.

## Проверка

### SEO и цели Метрики

Существующий счётчик задаётся через `SITE_YANDEX_METRIKA_ID`; второй счётчик
добавлять не нужно. Подтверждение Google и Яндекса через DNS не требует
дублирования meta verification в HTML. Подключение Метрики и подтверждение
прав на домен сами по себе не подтверждают попадание страниц в поисковый индекс.

В кабинете существующего счётчика проверьте цели и создайте отсутствующие
цели типа «Целевое событие» с условием «совпадает»:

- `bot_click` — переход в бота из любой части сайта.
- `watchlist_click` — переход в бота с конкретным фильмом/сериалом; также
  засчитывается `bot_click`.
- `channel_click` — переход в канал или к его публикации.

Код отправляет события через `reachGoal`, не задерживая переходы. Они означают
клик на сайте, а не успешный запуск бота или добавление в список ожидания.
Заблокированная Метрика не должна мешать навигации.

При обновлении Caddyfile на сервере примените конфигурацию командой
`docker compose exec -T caddy caddy reload --config /etc/caddy/Caddyfile`.
После этого `www.kinojdun.ru` должен отвечать постоянным перенаправлением на
`kinojdun.ru` с сохранением пути и параметров запроса.
Приложение также перенаправляет `www` на основной домен в публичном режиме,
поэтому правило работает и до перезагрузки конфигурации прокси.

В Search Console и Яндекс Вебмастере проверьте уже отправленный sitemap,
статус индексации главной, карточек и статей, причины исключения страниц.
Sitemap не требуется отправлять заново при каждом добавлении карточки.

```powershell
.venv/Scripts/python.exe -m unittest tests.test_website -v
.venv/Scripts/python.exe -m unittest discover tests
```

## Карточки и постепенная публикация

Первая успешная подборка формирует 50 карточек (25 фильмов и 25 сериалов):
новинки за последние 180 дней, будущие премьеры на год вперёд и продолжающиеся
сериалы с ближайшим эпизодом. Выборка отсортирована по популярности TMDB.
Начальные 50 карточек доступны сразу. Новые проекты сохраняются в очереди `catalog`
и ежедневно открываются по 3, по Москве.
Если публикуется новость о фильме или сериале с известным TMDB ID, его карточка
создаётся или открывается сразу, включая ранее скрытые карточки. Это отдельный
поток: карточки по новостям не расходуют дневную квоту обычного пополнения каталога.
Существующие карточки не дублируются. При запуске восстанавливаются карточки для
старых новостей; описание, постер, рейтинг и трейлер дополняются из TMDB.
Если TMDB временно недоступен, карточка доступна по сохранённым сведениям,
а загрузка подробностей повторяется при следующей синхронизации.

Повторные проверки и перезапуски обычной очереди не превышают дневную квоту; пропущенные дни
не вызывают массовую публикацию. `/movies`, `/series`, главная и sitemap
показывают только открытые карточки, скрытая карточка отвечает 404.

Отбор: не adult, есть постер и описание, popularity от 5; при 50 голосах
рейтинг должен быть не ниже 6.0. Мало голосов не означает низкий рейтинг:
ожидаемые проекты проходят по популярности. Это показатель интереса TMDB,
а не отдельная метрика ожидаемости. Пороговые настройки: `SITE_MIN_RATING`,
`SITE_MIN_VOTES`, `SITE_MIN_POPULARITY`, дневная квота — `SITE_DAILY_CARDS`.

Сайт проверяет все 50 проектов каждый час и обновляет карточки. Официальные
YouTube Trailer запрашиваются на русском и английском; русские имеют приоритет.
Первое обнаружение старого трейлера заполняет карточку без архивной новости.
Новые ролики после сохранённого снимка создают новости по ID видео без дублей.
Плеер доступен на карточке и в новости, предусмотрена ссылка на YouTube.
Доступность ролика и разрешение на встраивание определяются его владельцем.

Проверенная подборка 50 проектов от 05.10.2026 находится в
`website/catalog_seed.json`. При первом запуске новой версии она переносится
в каталог, все 50 карточек сразу становятся доступны. Следующий запуск
не восстанавливает удалённые карточки и не меняет очередность. Реальные
данные затем обновляются через TMDB; статический список не подменяет снимки.
Разговорные и новостные передачи, реалити и мыльные оперы исключены из отбора.

## Проверка дизайна

`/catalog` объединяет фильмы и сериалы; `/movies` и `/series` показывают
соответствующие проекты. Поиск, жанры, минимальный рейтинг и сортировка
работают на сервере без зависимости от JavaScript. На телефонах фильтры
сворачиваются, каталог показывает два постера в строке. Страница проекта
содержит фон, постер, описание, даты, трейлер и похожие проекты.
Версия CSS/JS включена в URL по хэшу содержимого: браузеры и CDN получают
новые стили после каждого обновления, не смешивая их со старым HTML.
Редакция ежедневно ищет новые подходящие проекты; запас очереди ограничен
12 карточками, публикация сохраняет квоту по 3 в день.


## История новостей и переходы из бота

Каждая карточка содержит раздел «История новостей»: все материалы с тем же
типом проекта и TMDB ID, от новых к ранним, с датами и ссылками на публикации.
История разбита на страницы по 20 записей (`news_page`); общая лента не ограничивает
доступность старых материалов конкретного фильма или сериала.

Названия проектов в сообщениях бота ведут на `/title/movie/<id>` или
`/title/tv/<id>`. Кнопка «Карточка и новости на сайте» доступна в предпросмотре,
уведомлениях и экранах отслеживания и шеринга. `SITE_BASE_URL` задаёт домен ссылок.
Если карточки ещё нет, при переходе загружаются сведения TMDB и карточка сразу
открывается вне очереди обычного пополнения. Этот переход не создаёт новости.
При временной ошибке TMDB страница предлагает повторить загрузку.
